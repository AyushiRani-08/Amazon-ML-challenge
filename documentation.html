Business Entity Resolution Pipeline Documentation

Model: LightGBM Metric: F-0.5 Score Stack: Pandas, Scikit-learn, Jellyfish

A complete, end-to-end Machine Learning pipeline tailored for resolving millions of noisy business entity records across multiple sources. The architecture strictly adheres to vectorized operations to bypass row-wise loops, maximizing speed and scalability.

Pipeline Architecture

1. Data Normalization normalize.py

  • Applied Unicode NFKC normalization, case-folding, and robust punctuation stripping using regex.
  • Implemented a generic legal-suffix normalization table (e.g., Corp → corporation, Pvt → private, & → and).
  • Expanded address abbreviations (Rd → road, St → street) and extracted core components like postal codes and numbers.

2. Candidate Generation (Blocking) blocking.py

  • Replaced exhaustive cross-joins with an efficient Union Blocking Strategy.
  • Phonetic Blocking: Applied Jellyfish's Double Metaphone/Soundex on names.
  • Token Overlap: Exploded the longest token for overlapping constraints.
  • Address Bucket: Merged directly on extracted postal codes.
  • Included built-in validation logic to track recall @ candidate set & reduction ratios.

3. Feature Engineering features.py

  • Vectorized complex string similarity algorithms across candidate pairs.
  • Computed Jaro-Winkler and Levenshtein ratios for Names & Addresses.
  • Generated Token Jaccard Similarity & Numeric Address Overlap.
  • Implemented TF-IDF Cosine Similarity trained dynamically over candidate sets for deeper contextual alignment.
  • Included explicit country matching flags as a feature (preventing hardcoded filtering).

4. Model Training train_model.py

  • Dynamically built training datasets matching Ground Truth positives against blocked negative samples.
  • Maintained a rigorous 1:5 Positive-to-Negative ratio to handle label imbalance.
  • Trained a highly optimized LightGBM binary classifier, respecting the strict < 8B parameters rule.

5. Thresholding & Predictions threshold_and_predict.py

  • Performed aggressive threshold sweeping on validation data to explicitly maximize the F-0.5 score.
  • Applied Global Consistency Resolution using confidence-based greedy assignments to prevent multiple S1 assignments to the same noisy entity.
  • First-class handling of singleton entities (yielding full F-0.5 credit).

6. Custom Evaluation evaluate.py

  • Constructed a customized metric script strictly evaluating the macro-averaged, per-entity F-0.5 formulation.
  • Penalizes precision errors 2x over recall, matching hackathon rules exactly.

7. Submission Generation make_outputs.py

  • Orchestrates the entire pipeline from raw unseen test data straight to required submission TSVs.
  • Outputs strictly tab-separated matching_results.tsv and candidate_pairs.tsv.
  • Automatically shells out to utils/validate_submission.py (if available) for pre-submission sanity checks.
